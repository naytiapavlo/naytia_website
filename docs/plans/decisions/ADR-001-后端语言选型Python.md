# ADR-001 · 后端语言选型：Python

日期：2026-09-16  
状态：已接受（用户指定后端使用 Python）  
关联需求：`../05-阶段计划与任务清单.md` 阶段 4、D07；`../02-总体架构与扩展规范.md` 第 1/4 节；`../03-内容模型与工具接入协议.md` 第 3 节  
替代记录：无

## 背景

论坛与账号系统（2026-09-16 纳入范围）需要服务端认证与持久化。前端与内容层建议基线为 Astro + TypeScript（D02）；服务端此前未定语言（D07 待决策项）。当前 Demo 仅用 localStorage 模拟，无服务端代码。约束：个人维护成本低、接口契约已在 03 文档定义（`ThreadRepository` / `SessionProvider`）、权限与密码哈希必须在服务端完成。

## 选择

| 方案 | 收益 | 成本与限制 |
| --- | --- | --- |
| A. Python（FastAPI 基线） | 用户指定；pydantic 校验与 OpenAPI 文档自动生成，可与前端 TS 契约联动；生态成熟（passlib/argon2、SQLAlchemy）；异步支持足够 | 前后端跨语言：类型契约不能直接共享，需以 JSON Schema/OpenAPI 为单一事实源并生成 TS 类型；部署需长驻进程或支持 Python 的平台 |
| B. Node.js + Hono/Fastify | 与前端同语言，类型直接共享；部署选择多 | 与已定方向冲突，仅作为备选记录 |
| C. Django 全栈 | 自带 admin/认证/ORM | 对「薄 API」场景过重；模板与静态站职责重叠 |

## 决定

后端使用 **Python**。建议基线框架 **FastAPI**（正式初始化时锁定版本并记录），校验用 pydantic，密码哈希用 argon2id。数据库已定 **SQLite**（2026-09-16 用户确认）：文件型、零运维、便于随仓库外备份，统一通过 SQLAlchemy 访问，保留迁移 Postgres 的路径（仓储接口不暴露 SQL 方言）。适用范围：账号（注册/登录/会话）、论坛读写、工具箱个人数据三类 API；博客/作品/工具目录仍为静态预生成，不经过 Python 服务。暂不覆盖：托管平台选择、管理后台。

跨语言契约约定：03 文档的模型与接口以 **JSON API + OpenAPI Schema 为单一事实源**——后端 pydantic 模型生成 OpenAPI，前端由 OpenAPI 生成 TypeScript 类型并映射到仓储接口；两侧不得各自手写漂移的字段定义。

## 扩展影响

- `02` 分层不变：适配器从「local（localStorage 演示）」换为「http + python 服务」，页面与仓储接口不感知。
- `03` 契约不变：`ThreadRepository` / `SessionProvider` 语义由 Python 实现承载；错误返回需映射为既定 `ToolError` 风格的结构化错误。
- 阶段 4 任务「服务端账号/论坛 API」改按 Python 实现；前端演示版无需改动。
- 新增依赖：FastAPI、uvicorn、pydantic、SQLAlchemy、argon2 相关库、限流中间件；版本在实现初始化时锁定。

## 数据与回退

当前无服务端数据，无迁移。正式实现时：SQLite 建表（accounts / threads / replies）→ 演示数据不迁移（界面已明示演示边界，正式上线数据重新开始）→ 数据库文件与代码分开备份 → 回退方式为保留静态站独立可用（02 文档「云端功能失败时静态内容与本地工具仍可使用」）。

## 重新评估条件

托管平台确定后若无法长驻 Python 进程且平台函数计算不支持；或出现需要与前端共享大量实时计算逻辑（同语言收益显著）的场景，重新评估语言选择。框架层面若 FastAPI 无法满足性能或维护需求，可在语言不变的前提下更换。数据规模或并发写入超出 SQLite 适配范围（多进程高并发写、多实例部署）时，经迁移脚本切换 Postgres，仓储接口与页面不变。
