# ADR-005 · 开放工具 API 体系（v1）

日期：2026-09-16  
状态：已接受（用户要求：构建网站 API 体系，让外部开发者通过 API 使用工具箱工具，并制定 API 标准）  
关联：`../09-开发者API标准.md`（对外标准全文）、`../03-内容模型与工具接入协议.md`（工具协议）、ADR-001（后端选型）  
替代记录：无

## 背景

工具箱引擎目前只在前端 TS 中运行（`src/tools/`），外部程序（机器人、脚本、第三方页面）无法使用。需要一套公开、稳定、可演进的服务端 API，并明确标准：版本化、统一信封、错误码、认证、限额与可追溯性。约束：引擎语义必须与前端一致（同一规则集两个实现，共享对照用例）；后端为 FastAPI 单体（ADR-001）；不引入新基础设施。

## 选择

| 方案 | 收益 | 成本与限制 |
| --- | --- | --- |
| A. Python 移植引擎 + `/api/v1` 公开路由（信封 + 密钥 + 进程内限流） | 零新依赖；语义由共享测试用例锁定；OpenAPI 自动生成对外文档 | 引擎需两端同步升级（以 ruleset_id 换版管理） |
| B. 前端引擎跑在 Node sidecar | 无需移植、天然一致 | 多一个运行时与部署单元，违背单体起步约定 |
| C. 页面内 WASM 引擎对外服务 | 单一实现 | 复杂度高，不适合 v1 |

## 决定

采用 A。要点：

1. **版本化**：URL 主版本 `/api/v1`；响应 `meta` 携带 `tool_id / implementation_version / input_schema_version / ruleset_id / duration_ms`；请求可固定 `ruleset_id`（不匹配 → `unsupported_ruleset`）。破坏性变更升 v2，v1 保留 ≥6 个月。
2. **统一信封**：成功 `{ok, data, warnings?, meta}`；失败 `{ok:false, error:{code,message,field,retryable}}` + 正确 HTTP 状态码；错误码表见 09 文档第 5 节。
3. **认证与限额**：匿名 30/min/IP；`Bearer nk_…` 密钥 300/min/密钥。密钥由超管在 `/api/admin/api-keys` 签发/停用，库中仅存 SHA-256。限流为进程内滑动窗口（单进程），多实例时迁 Redis。
4. **范围**：仅 `stable`/`experimental` 工具进入 v1（当前：区块与坐标助手、材料清单助手）。输入上限：64KB / 40 条 / ±29,999,999。API 对 `dimension` 等字段**严格校验**（不静默默认），比前端表单更严格并在 Schema 中注明。
5. **目录快照**：`public_api/catalog.py` 是服务端工具元数据权威快照，与前端 manifest 同步维护（id/版本/规则集一致）；工具 JSON Schema 随详情接口下发。
6. **模块归属**：全部代码在 `backend/app/public_api/`（模型 `models/developer.py`），`main.py` 仅一行 `public_api_router.register(app)`——符合模块解耦约定（ADR-002）。

## 扩展影响

- 前端无需改动；新工具进入 v1 = 新增引擎移植 + 目录快照一条（并行开发边界不变）。
- CORS：v1 暂沿用站点同源策略；外部浏览器直连场景随 D07 部署形态开放 `*`（服务端间调用不受影响）。
- 后续演进：自助申请密钥（绑定账号）、用量统计、Webhook/批量端点、Redis 限流——各自独立交付。

## 数据与回退

- 新表 `api_keys` 由 `create_all` 自动建表；密钥明文仅签发时返回一次。
- 回退：从 `main.py` 移除 `register(app)` 一行即整体下线，不影响站内功能；限流计数器随重启清零。

## 验证

- pytest 16 项（`tests/test_public_api.py`）通过：目录/详情/执行、与前端共享的边界用例（-17/-16/-1/0/15/16、混合堆叠 + 容器折算）、错误码信封、规则集固定、匿名 30/min 限流与 `Retry-After`、密钥签发/高限额/停用/坏密钥。全后端 206 项测试通过。
- 待办：正式域名（D05）确定后补「使用条款」全文与外部可访问的 HTTPS 地址。

## 重新评估条件

调用量增长使进程内限流与单机 SQLite 成为瓶颈、或出现付费档位/SLA 需求时，重新评估为 Redis 限流 + 独立网关。
