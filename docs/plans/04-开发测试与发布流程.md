# 04 · 开发测试与发布流程

更新日期：2026-09-16  
状态：未来正式项目的工程约定。本次没有安装依赖、搭建 CI 或执行发布。

## 1. 开发起步

1. 备份并验证当前 Demo，处理现有手写 `dist/` 与未来构建输出的冲突。
2. 记录技术选型 ADR，确定运行时、包管理器、框架和托管方式。
3. 锁定所选依赖版本与 lockfile；不把文档中的“建议技术”当作未经验证的安装指令。
4. 建立 TypeScript 严格检查、必要的格式和静态检查、生产构建。
5. 创建开发、预览、生产配置；生产地址只在托管目标确定后填写。
6. `.env.example` 只写变量名与非敏感示例；前端可公开配置与服务端秘密变量分开。

建议脚本名称：`dev`、`build`、`preview`、`check`、`test`、`test:e2e`、`validate:content`。实际命令以初始化后项目为准，当前 Demo 不具备这些脚本。

## 2. 内容发布流程

作者编辑文章/作品 → 本地预览 → schema 与引用检查 → 构建预览 → 检查正文/资源/版本 → 合并并部署。

- 构建阶段检查 ID 和 slug 唯一、必填字段、无效日期、引用目标、资源路径、非法状态及不可信协议链接。
- 统一过滤草稿，覆盖列表、详情、关联推荐、RSS、站点地图与搜索索引。
- 外部链接可提供人工检查入口或周期检查，暂时不可达与确定失效分开处理。
- 大体积存档通过资源存储提供；仓库只保留清单与小型测试夹具。
- 资源替换创建新版本，避免同一个版本号悄悄变成不同文件。

## 3. 按风险分配测试

| 层级 | 主要验证 | 不做什么 |
| --- | --- | --- |
| 纯计算 | 独立已知结果、边界值、非法输入、不变量 | 不只用代码本身推导预期值 |
| 协议/schema | 序列化、版本迁移、拒绝非法内容 | 不假设类型检查能替代运行时验证 |
| 模块集成 | 注册工具、载入规则、关联内容、资源清单 | 不为每条 CSS 写单元测试 |
| 关键端到端 | 读文章、找作品、执行工具、失败恢复 | 不重复覆盖所有底层数值组合 |
| 视觉与可访问性 | 手机/桌面、键盘、缩放、颜色、长文本 | 不把“能构建”当作视觉通过 |

### 首批工具的必要样例

- 区块坐标：`-17/-16/-1/0/15/16` 等边界；验证区块内坐标范围与反向还原关系。
- 材料计数：0、1、堆叠上限前后、16/64/不可堆叠物品、非整数、负数和安全整数边界。
- 时序换算：单位区别、零/负数、精度、名义 tick rate 与实际速率的说明。
- 重任务：运行中取消、快速重复运行、切页、旧任务晚返回、超限和 Worker 错误。
- 文件分析若未来加入：空文件、损坏/截断、错误版本、超大声明长度、压缩膨胀和编码差异。

## 4. 性能目标

以下为建议初始预算，建立实测基线后可通过 ADR 调整；不作为当前 Demo 已达成的指标。

- 首页与文章页尽量不加载工具代码；首屏必要站点 JS 的 gzip 预算暂定 80 KB，不含用户点击后加载的工具和外部播放器。
- 普通轻量工具交互目标为常见设备 100 ms 量级内反馈；较长任务离开主线程，并提供真实的忙碌状态。
- 头像/封面有明确尺寸与替代文本，优先合适的压缩格式，减少页面位移。
- 工具依赖按路由懒加载；不会因为加入一个 WASM 引擎，让每篇文章都加载它。
- 性能记录注明浏览器、设备、网络、输入规模及冷/热缓存，避免脱离环境比较数字。

## 5. 安全与数据边界

- 首版计算尽量在浏览器本地完成；文件处理明确说明是否上传，不悄悄传输存档或种子。
- Markdown HTML 默认禁用或经过消毒；未来用户评论不使用可信作者 MDX 流程。
- 资源地址采用允许的协议；外链不接受脚本协议。
- 未来 API 校验输入、权限、大小、配额；限流、密钥与授权仅在服务端处理。
- 研究脚本、源码分析输出、开发日志不会因放在仓库里就自动成为公开资源。
- 分析与错误上报只收集必要信息，不记录完整用户输入、种子、文件或凭据。
- 依赖增加需要具体用途；版本更新先验证兼容性，再合并发布。

## 6. 发布与回退

第一版以静态产物部署为默认方向，托管商、域名、访问地区和成本尚未确定。选定平台后验证直达详情页、404、缓存和资源下载，再记录专用发布手册。

CI 的建议顺序：锁定安装 → 类型/静态检查 → 内容校验 → 核心算法测试 → 生产构建 → 关键路径验证 → 预览或发布。失败停止发布，不能发布部分构建。

每次发布记录代码修订、构建配置、内容版本与资源清单。保留上一稳定产物及恢复步骤；有数据库后另设迁移与备份策略，回退代码不等于自动回退数据。

缓存采用带内容指纹的静态资源；内容 HTML 保持合适的刷新策略。不能长期缓存旧 HTML 导致新资源路径失配。

## 7. 上线验收清单

- [ ] 头像、简介、署名、公开链接已确认，示例内容已替换或不进入正式站。
- [ ] 四项导航（首页 / 作品 / 工具箱 / 论坛）及全部详情 URL 可直接访问、刷新和返回；注册登录流程可用。
- [ ] 文章/作品的标题、描述、canonical、RSS 与站点地图符合实际。
- [ ] 草稿、研究材料、密钥及私有资源不在发布产物中。
- [ ] 工具算法有独立对照样例，适用版本与限制可见。
- [ ] 手机/桌面布局、键盘、200% 缩放和必要错误状态验收通过。
- [ ] 资源下载地址、版本、体积与校验值匹配。
- [ ] 明确记录平台配置、备份位置、上一稳定版本和回退流程。

## 8. 持续维护

内容更新及时记录；游戏版本变化后按工具/作品分别复测，而不是全站统一宣称兼容。暂未验证的版本保留不确定状态。

依赖、安全、资源可达性与性能按发布节奏检查。发生故障先确认影响范围、停用故障模块或回退，再记录原因、修复与防止复发的验证。
