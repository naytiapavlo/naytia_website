# 03 · 内容模型与工具接入协议

更新日期：2026-09-16  
状态：设计契约草案。代码片段用于约束未来实现，不是当前可运行源码。

## 1. 通用约定

- `id` 是稳定标识，`slug` 是可读 URL 名称；重命名不更改 ID。
- 时间采用含时区的 ISO 8601；显示层再按站点配置格式化。
- 内容契约版本、工具实现版本、工具输入协议版本、MC 规则版本彼此独立。
- 标签引用稳定 ID，显示名可变；引用目标必须存在且满足公开状态。
- 数值单位明确：方块坐标、区块坐标、game tick、second 等不使用无单位字段名。
- 种子等超出 JavaScript 安全整数范围的数据在 URL/JSON/输入中使用十进制字符串；计算边界再转换为 `bigint`。
- 不能用浮点版本号表示 `1.21.100` 等游戏版本。

## 2. 内容模型

| 模型 | 首版核心字段 | 可扩展字段 |
| --- | --- | --- |
| `SiteConfig` | 名称、头像、简介、导航、公开外链、locale、timezone | 首页区块顺序、功能开关、主题 |
| `Post` | id、slug、schemaVersion、title、summary、body、status、tags、publishedAt、updatedAt | 系列、作者、引用、关联作品与工具 |
| `Work` | id、slug、schemaVersion、title、summary、body、type、status、tags、authors | 版本验证、视频、资源、更新记录、替代作品 |
| `ResourceRelease` | id、workId、version、name、format、location | 字节大小、SHA-256、适用环境、许可证、镜像 |
| `ContentReference` | kind、id | 跳转锚点、关联说明 |
| `CompatibilityClaim` | edition、distribution、gameVersion、verificationStatus | 平台、验证日期、测试环境、来源、限制 |
| `ForumCategory` | id、slug、title、顺序、状态 | 版块介绍、权限差异 |
| `ForumThread` | id、schemaVersion、categoryId、title、authorId、body、status、createdAt、lastActivityAt | 置顶、锁定、编辑历史 |
| `ForumReply` | id、threadId、authorId、body、createdAt | 引用父回复、状态 |
| `Account` | id、name（唯一）、displayName、createdAt | 角色、邮箱、第三方绑定 |

`status` 用于发布状态，如 `draft/published/archived`。机器可用性由独立的 `verificationStatus` 表达，如 `verified/unverified/broken`，不能把“已发布”解释为“当前版本可用”。

版本兼容性优先记录明确的已测版本；只有证据支持时才声明范围。`edition`（Java/Bedrock）与发行渠道、平台、正式/预览版本分开。遇到未知值显示未知，不填造假的默认值。

正文渲染与查询元数据分离：列表查询不携带完整正文，详情通过内容引用加载。MDX 若启用，只接受仓库内可信作者内容，不执行外部提交的代码。

## 3. 内容源接口

```ts
interface PageResult<T> {
  items: T[];
  nextCursor?: string;
}

interface PostRepository {
  listPublished(input: {
    tagId?: string;
    cursor?: string;
    limit: number;
  }): Promise<PageResult<PostSummary>>;
  getPublishedBySlug(slug: string): Promise<PostDetail | null>;
}
```

`PostSummary` / `PostDetail` 的正式类型由对应 schema 生成或保持一致。作品使用独立的 `WorkRepository`，不强行塞进文章字段。构建层负责把内容详情转换为当前框架的可渲染正文；纯领域层不返回框架组件。

论坛与账号（2026-09-16 纳入范围）使用同风格的独立接口，不塞进 `PostRepository`：

```ts
interface ThreadRepository {
  listThreads(input: {
    categoryId?: string;
    cursor?: string;
    limit: number;
  }): Promise<PageResult<ThreadSummary>>;
  getThread(id: string): Promise<ThreadDetail | null>;
  createThread(input: { categoryId: string; title: string; body: string }): Promise<ThreadDetail>;
  addReply(threadId: string, body: string): Promise<ForumReply>;
}

interface SessionProvider {
  current(): Promise<AccountSummary | null>;
}
```

`createThread/addReply` 隐含「必须已登录」，由服务端以会话判定并返回结构化错误；本地演示适配器以 localStorage 模拟同一契约。正式服务端为 Python（见 ADR-001）：本节模型与接口以 JSON API + OpenAPI 为单一事实源，后端 pydantic 模型生成 OpenAPI，前端 TypeScript 类型由 OpenAPI 生成，两侧不得各自维护漂移的字段定义。用户帖子与回复正文为纯文本并转义渲染，不进入可信作者 MDX 流程。

最小列表接口提供排序和稳定分页语义；接口不能泄露文件绝对路径或 CMS 私有字段。公开查询默认排除草稿与不可公开资源。

## 4. 工具声明

```ts
type ToolStatus = 'planned' | 'experimental' | 'stable' | 'deprecated';
type ExecutionMode = 'inline' | 'worker' | 'wasm-worker' | 'server';

interface ToolManifest {
  id: string;
  slug: string;
  title: string;
  summary: string;
  category: string;
  tags: string[];
  status: ToolStatus;
  implementationVersion: string;
  inputSchemaVersion: number;
  executionMode: ExecutionMode;
  supportedRulesetIds: string[];
  relatedContent: Array<{ kind: 'post' | 'work'; id: string }>;
}
```

列表只载入上述可序列化元数据。`loadView/loadEngine` 留在构建时注册表中，不写入内容 JSON。工具宿主可读取会话状态（`SessionProvider`）提供登录门槛与按账号收藏；工具计算本身不依赖账号，纯函数契约不变。每个可运行工具至少包含：

```text
manifest.ts         元数据
schema.ts           输入输出运行时校验与类型
engine.ts           独立于 UI 的计算逻辑
ToolView.tsx        专用输入输出呈现
examples.ts         可运行示例与预期结果
engine.test.ts      正常、边界与失败用例
README.md           算法依据、限制、版本说明
worker.ts           仅耗时工具需要
```

通用字段可以复用表单组件；复杂画布、地图、文件分析使用专用 UI，不强制把所有工具压进自动表单。

## 5. 引擎、校验与错误

```ts
type ToolError = {
  code: string;
  message: string;
  field?: string;
  retryable: boolean;
};
type ToolResult<T> =
  | { ok: true; value: T; warnings: string[] }
  | { ok: false; error: ToolError };

interface ComputeContext {
  rulesetId: string;
  signal: AbortSignal;
  reportProgress?: (completed: number, total?: number) => void;
}
interface ToolEngine<I, O> {
  run(input: I, context: ComputeContext): Promise<ToolResult<O>>;
}
```

宿主接收原始输入后先运行 schema 校验，再选规则、调用执行适配器；不对非法值“猜测修复”。错误按输入错误、规则不支持、资源超限、已取消、内部故障分类。

上述 `ComputeContext` 仅用于进程内调用；不能把函数或 `AbortSignal` 当成 Worker/HTTP 消息直接发送。Worker 适配器负责协议转换，服务端适配器必须再次校验。

## 6. Worker 与重任务协议

```ts
type RunMessage = {
  type: 'run';
  protocolVersion: 1;
  jobId: string;
  toolId: string;
  rulesetId: string;
  inputSchemaVersion: number;
  input: unknown;
};
type CancelMessage = { type: 'cancel'; jobId: string };
type WorkerReply =
  | { type: 'progress'; jobId: string; completed: number; total?: number }
  | { type: 'result'; jobId: string; result: ToolResult<unknown> }
  | { type: 'cancelled'; jobId: string };
```

- `jobId` 隔离新旧计算；已经过期的结果不能覆盖当前输入的结果。
- 取消不能只改按钮文字：算法分批让出执行权并检查取消，或宿主终止专属 Worker 并重建；紧密同步循环不能指望及时处理取消消息。
- 每个引擎配置合理的输入量、时间和内存预算；超限提示缩小范围，不无限制分配数组。
- 进度未知时使用不确定状态，不伪造百分比。
- 离开工具页释放 Worker、对象 URL 与大缓存；任务失败恢复到可再次运行的状态。
- 首版任务预算在获得实际算法与设备测量后记录，不假设所有工具同样快。

## 7. 规则版本与可复现性

每次结果应能关联：工具 ID、实现版本、输入协议版本、规则集 ID、规范化输入和重要警告。导出格式包含 `exportSchemaVersion`，后续导入先识别版本再迁移。

缓存键至少包含工具 ID、实现版本、规则集 ID、规范化输入摘要；不得只用输入文本作缓存键。格式或规则改变时失效旧缓存；缓存不是结果真实性的来源。

一个规则集记录支持的版本/发行渠道、规则来源、验证样例与限制。找不到匹配规则时停止或明确切换到用户选择的实验模式，不冒充兼容。

## 8. 新增工具的标准流程

1. 写清玩家需求、输入输出、适用范围和非目标。
2. 收集至少一个独立依据或可复现游戏样例，区分已验证结论与猜测。
3. 编写 manifest 与输入输出 schema，选择最简单可行的执行模式。
4. 先实现纯算法与边界验证，再接 UI；根据实际耗时决定是否 Worker 化。
5. 新增专属目录，并在注册表加入一项；目录与详情路由由宿主生成。
6. 补齐错误、空状态、版本说明和需要的导出功能。
7. 通过针对算法、输入校验、性能与浏览器兼容性的检查后标记可用。

验收：新增工具不需要修改其他工具；不存在全局 `switch(toolId)` 堆积所有算法；未启用的工具不被打包进入所有页面。
