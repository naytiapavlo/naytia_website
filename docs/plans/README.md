# Naytia 个人网站 · 项目规划文档

更新日期：2026-09-16  
状态：建设计划 v1.1，待实施。本文档中的技术方案是建议基线，不表示已经安装、部署或验证了正式项目。2026-09-16 变更：按用户要求将「论坛模块」与「注册登录账号系统」纳入产品范围，并在静态 Demo 中追加对应演示实现。

## 项目目标

构建属于 Naytia_帕芙洛的个人网站，提供个人博客、作品展示、Minecraft 技术玩家工具箱和玩家论坛。视觉沿用白色、简约、可爱像素风；顶级导航固定为「首页 / 作品 / 工具箱 / 论坛」，博客入口与最近文章放在首页。

网站提供注册登录账号系统；账号同时作用于论坛（发帖、回复需登录）与工具箱（收藏与个人使用记录需登录），博客与作品的阅读、论坛与工具目录的浏览不需要账号。

所有功能以长期可扩展为目标：新增内容不改页面模板，新增工具不修改其他工具，更换数据来源不重写业务规则，更换主题不修改计算代码。

## 已有内容与边界

- **正式工程已初始化（2026-09-16）**：Astro 5 + TypeScript 前端（`src/`、`content/`）与 FastAPI + SQLite 后端骨架（`backend/`）；构建、类型检查与后端测试已通过。运行方式见根 `README.md`。
- **工具系统已实装（2026-09-16，阶段 3）**：工具宿主 + `/tools/[slug]/` 详情路由 + 登录后收藏已打通。
  当时的两个工具（区块坐标助手、材料清单助手）**已于同日按需求移除**，当前工具为
  **`.mcstructure` 编辑器**（上传 / 查看 / 编辑 / 下载）。宿主实装证据见
  [`06-开发日志-工具系统实装.md`](06-开发日志-工具系统实装.md)（含移除说明），
  当前工具的实装与验证见 [`08-开发日志-mcstructure编辑器.md`](08-开发日志-mcstructure编辑器.md)。
  历史实现可从 git 提交 `fa47d7b` 取回。
- **逆向工作台已实装（2026-09-16）**：从工具箱跳转的独立页面 `/ida/`，在线浏览 BDS（`bedrock_server.exe` 1.21.1.03）的反汇编与 Hex-Rays 伪代码；后端代理本机 `ida-pro-mcp`，**访客只读、admin 可重命名函数**、管理员可切换 IDA 实例。`patch` / `py_eval` 等任意执行能力刻意不开放。决策与安全边界见 [`ADR-004`](decisions/ADR-004-在线逆向工作台代理IDA-MCP.md)，验证证据见 [`07-开发日志-逆向工作台.md`](07-开发日志-逆向工作台.md)。
- `prototypes/pixel-demo/`：手写静态 Demo 的存档（含演示版论坛/账号交互，SHA-256 校验一致）；`dist/` 现为构建产物目录，不入库。
- `public/avatar.png`：生成的示意头像；上线前需要替换或明确决定继续使用。
- **结构文件解析接口已实装（2026-09-16，阶段 6「文件导入导出」提前落地）**：只读的 `.mcstructure` 解析 API（`POST /api/mcstructure/{parse,voxels,slice,position,blocks}`、`GET /api/mcstructure/info`），可解析完整结构、方块实体 NBT 与实体 NBT。这是**唯一需要上传文件**的功能，与工具箱「计算在浏览器本地完成」的默认口径不同，已在接口说明与前端模块注释中写明；决策见 [`ADR-003`](decisions/ADR-003-基岩版结构文件解析器.md)。
  - 2026-09-16 追加：论坛附件也要求上传，站点上需要上传文件的功能从「唯一」变成「两处」；两处共用同一份上传读取与错误码（`backend/app/uploads.py`）。
- **论坛附件与网页 3D 预览已实装（2026-09-16，阶段 4）**：发帖时可随帖上传 **`.mcstructure` 结构文件**（≤10 MB）与**封面图**（≤5 MB，PNG/JPEG/GIF/WebP），两者各自可选。结构文件由内置解析器解析出**材料清单**（按方块排列统计、剔除空气并如实单列），并生成一份「占用位图 + 调色板下标」的轻量载荷；网页端用自实现的 Canvas 2D 体素渲染器画出 3D 预览（拖动旋转、滚轮缩放、分层查看），附件可下载。封面在列表显示 16:9 懒加载缩略图、详情页显示原图，作者与管理员可删除，**类型只认文件头字节**（拒绝 SVG）并提供 `nosniff` 与 CSP。决策见 [`ADR-006`](decisions/ADR-006-论坛结构附件与网页3D预览.md)，实装与验证证据见 [`10-开发日志`](10-开发日志-论坛结构附件与3D预览.md)。已知限制：无存储配额与限流、颜色为示意色、超大结构会抽稀、封面不做服务端压缩。
- `ancient_debris/`：研究目录（438MB），按 04 文档不入库，需另行备份；不把它视为已完成的网站工具。
- **作品页三个新区块已实装（2026-09-16）**：动态滚动的作品封面（一行无缝循环、悬停暂停、点击看大图）、研究时间轴（滚动进度线 + 节点浮现）、B 站视频成果清单（纯文本）。原有的「作品档案」卡片区块按站长要求删除，作品页只保留这三段。封面数据与文案在 `src/modules/works/data.ts`。实装与验证证据见 [`11-开发日志-作品页封面滚动与时间轴.md`](11-开发日志-作品页封面滚动与时间轴.md)。
- **文档树工具已实装（2026-09-16）**：工具箱里新增的独立页面 `/docs/`，**访客可公开阅读与搜索**，管理员可上传文件与新建文件夹，但改动以「提交单」形式排队、由超级管理员审核通过后才真正对访客开放。首版收进 `Minecraft\doc` 的 120 篇文档（58 md / 51 txt / 14 json，8 个文件夹）；`backend/scripts/import_docs.py` 可幂等重复导入。决策见 [`ADR-007`](decisions/ADR-007-文档树与审核发布流程.md)，实装、验收与已知限制见 [`12-开发日志-文档树工具.md`](12-开发日志-文档树工具.md)。
- **部署形态已定并本机验证（2026-09-16，D05）**：静态产物与后端 API 由本地入口
  `deploy/server.py` 收在 **同一个端口（127.0.0.1:8080）**，樱花 **HTTP 隧道**指向它，
  域名解析在 GoDaddy 侧配置。本机侧（静态页/接口/会话 Cookie/上传/真实 IP/全站链接）已逐项实测；
  **公网侧（隧道 + 解析 + https 下登录态）待用户在面板配置后走完验收清单**。
  决策见 [`ADR-009`](decisions/ADR-009-同源单端口部署与内网穿透.md)，
  操作步骤与验收清单见 [`14-部署手册`](14-部署手册-域名与内网穿透.md)。
- **超管账号管理页已实装（2026-09-16）**：`/admin/users/`——超管按名字搜索账号、
  把会员设为管理员、把管理员退回会员。搜索在服务端做（大小写不敏感的子串匹配，
  通配符已转义）；「设为管理员」走独立的 `/api/admin/accounts/{id}/admin`，契约上
  只覆盖 admin ↔ member 两档，**超管档位不在这里改**（只能由引导规则或邀请码产生）。
  决策见 [`ADR-010`](decisions/ADR-010-账号管理界面.md)，实装与验收见
  [`15-开发日志-账号管理页.md`](15-开发日志-账号管理页.md)。
- 当前没有自动部署流水线（改内容是「重新构建 → 入口直接读 `dist/`」，不需要重启）；
  博客/作品详情页（阶段 2）仍是待办。

## 文档使用约定

1. 后续需求、实现方案、技术决策、阶段复盘等 Markdown 统一放在 `docs/plans/` 下；网站访客阅读的博客放在未来的 `content/posts/`，两者分开。
2. 文件采用 `两位编号-中文主题.md`；独立决策放 `decisions/ADR-编号-主题.md`，使用模板记录。
3. 每份计划区分「已确认要求」「建议实现」「未来候选」；不得把计划中的功能写成已上线功能。
4. 大改需求先同步产品范围，再更新接口、任务与验收；不在多份文档重复维护互相冲突的字段定义。
5. 任务使用 `[ ]` / `[x]`，只有有可查验交付物及验收结果时才标记完成。
6. 文档不保存账号密码、密钥、未脱敏日志或未授权公开的数据。

## 可扩展性的验收标准

| 变化 | 允许的主要修改范围 |
| --- | --- |
| 发布文章、作品、资源更新 | 对应内容文件和资源清单 |
| 更换头像、简介、外链、首页推荐顺序 | 站点配置与素材 |
| 新增一个工具 | 新工具目录、显式注册项、对应测试 |
| 增加一种计算实现 | 工具引擎及其适配器、规则版本与测试 |
| 更换文件内容源为 CMS | 内容适配层、发布流程、必要的数据迁移 |
| 更换视觉主题 | 设计变量、组件样式与主题配置 |
| 新增服务端能力 | 新服务适配器与明确的 API 边界 |

架构允许扩展，但不承诺任意变更都零修改：新业务模型、登录权限、持久化和平台迁移仍需明确设计与验证。
