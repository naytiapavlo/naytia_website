# 14 · 部署手册：域名 + 内网穿透（樱花）+ 本机运行

状态：**本机侧已实装并验证**（2026-09-16）。域名 `naytia.io`（GoDaddy 注册）、
隧道类型 HTTP、解析方式 CNAME——第 3、4 节需要你在面板/DNS 里点几下，第 2、5 节已经跑通。

适用范围：把本机（Windows，跑着 Astro 产物 + FastAPI）通过**樱花的 HTTP 隧道**发布到
`https://www.naytia.io`。对应阶段清单里的 D05（托管与域名）与阶段 5 的发布任务。

**下一步只需三件事**（细节见第 3、4 节）：

1. 樱花面板建一条 **HTTP 隧道** → 本地 `127.0.0.1:8080`，绑定域名 `www.naytia.io`，开自动 HTTPS；
2. GoDaddy DNS 里把 `www` 的 CNAME 改成**樱花节点域名**（现在它指向裸域名，是停放页）；
3. 确认 `deploy\start-all.cmd` 的两个窗口在跑，然后按第 6 节的公网清单验收。

## 1. 这套部署长什么样

```
                    浏览器  https://www.naytia.io
                       │
                       ▼
        ┌──────────────────────────────┐
        │   SakuraFrp 节点（frps）      │  自动 HTTPS（证书在节点侧）
        └──────────────┬───────────────┘
                       │ frpc 建立的隧道（本机 frpc 进程）
                       ▼
        ┌───────────────────────────────────────┐
        │  deploy/server.py  127.0.0.1:8080     │  ← 隧道指向这里
        │  ├─ /             → dist/ 静态产物     │
        │  ├─ /_astro/*     → dist/（长期缓存）  │
        │  └─ /api/*        → 127.0.0.1:8000     │
        └──────────────┬────────────────────────┘
                       ▼
        ┌───────────────────────────────┐
        │  FastAPI  backend  127.0.0.1:8000 │  账号 / 论坛 / 文档树 / 工具 API
        └───────────────────────────────┘
```

只需要**一条隧道、一个端口**。

## 2. 为什么中间要加一层本地入口（而不是让隧道直接指向前端或后端）

这是本方案唯一的「架构决定」，理由都来自实际会遇到的问题（决策记录见
[`ADR-009`](decisions/ADR-009-同源单端口部署与内网穿透.md)）：

| 做法 | 结果 |
| --- | --- |
| 隧道 → Astro 静态服务（4321） | `/api` 无处可去，整个后端用不了 |
| 隧道 → 后端（8000） | 页面拿不到，后端不会替你发静态页面 |
| 开两条隧道：一条前端一条后端 | 站点变成**两个域名/两个端口**，浏览器视为跨站：会话 Cookie 被拦、CORS 预检要单独放行、`SameSite=Lax` 失效。项目里已经为此留过警告（`06-开发日志` 第 117 行的结论：**同域部署才可用**） |
| **隧道 → 本地入口（8080），入口内部分流** | 浏览器只看到一个来源，Cookie、CORS、相对路径全部按同源处理；隧道只要一条 |

入口本身**没有引入任何新依赖**：`httpx` + `uvicorn` 本来就在
`backend/requirements.txt` 里，代码是 `deploy/server.py`（约 500 行，含注释）。

## 3. 樱花隧道怎么配（管理面板里点）

> 樱花侧需要操作的部分如下；面板上的按钮名称以你看到的为准。

1. **建隧道**：类型选 **HTTP**，本地 IP `127.0.0.1`，本地端口 **8080**。
   - 一定要选 **HTTP 隧道**，不要选 TCP。两个原因：
     - HTTP 隧道带 `Host` 与 `X-Forwarded-*`，**访客真实 IP 才能传到后端**
       （樱花的 HTTP 隧道会把访客 IP 追加到 `X-Forwarded-For` 尾部，
       见 <https://doc.natfrp.com/bestpractice/realip.html>）。走 TCP 隧道时后端
       只会看到 `127.0.0.1`，AI 助手那类按 IP 记的配额会变成「所有访客共用一份」。
     - HTTP 隧道有「自动 HTTPS」，节点侧替你签证书，浏览器不会报证书错误。
2. **选节点**：节点列表里带绿色 **建站** 标识的才可以建 HTTP(S) 隧道。
   按樱花的[备案说明](https://doc.natfrp.com/faq/beian.html)：
   - **内地节点**：必须是**已备案**的域名，并在面板完成「验证备案」；
   - **境外/香港等节点**：不需要备案。
   `naytia.io` 未备案，**必须选境外/香港节点**。
3. **绑定域名**：填 **`www.naytia.io`**。
   - 必须和 DNS 里解析的主机名**完全一致**；`naytia.io` 与 `www.naytia.io` 是两个不同域名，
     不能互相顶替。
   - 一条隧道最多绑 3 个域名，用英文逗号分隔，**不支持泛域名**。
   - 想让裸域名 `naytia.io` 也能用，见第 4 节的「裸域名怎么办」。
4. **自动 HTTPS**：设为「自动」。隧道启动后日志里会出现
   `已从服务器为 www.naytia.io 加载证书`，看到这行就说明证书就绪。
   （首次签发可能要几分钟，期间出现 `Nyat APP SSL 证书签发中` 是正常的。）
5. 启动隧道，记下日志里给出的访问地址。

### 想先跳过 DNS：用樱花送的免费子域

樱花给所有用户提供免费的 `*.nyat.app` 子域与证书（管理面板 →「子域绑定」）。它**不经过
GoDaddy**，申请完把子域绑到这条隧道即可，等于跳过第 4 节的全部 DNS 操作。
适合先把站点跑通、之后再换成 `www.naytia.io`（只需改根 `.env` 的 `SITE_URL` 并重新构建）。

## 4. GoDaddy 解析怎么配（`naytia.io` 的具体填法）

### 先看现状（2026-09-16 实测）

```
naytia.io      A      13.248.243.5, 76.223.105.230     ← GoDaddy 停放页
www.naytia.io  CNAME  naytia.io                          ← 指向裸域名（也是停放页）
naytia.io      NS     ns57.domaincontrol.com / ns58.domaincontrol.com
```

也就是说**现在两条记录都指向 GoDaddy 的停放页，必须改**。

### 要做的改动

在 GoDaddy 的 DNS 管理页（我的域名 → `naytia.io` → DNS / 管理 DNS）：

| 操作 | 类型 | 名称（主机） | 值 | TTL |
| --- | --- | --- | --- | --- |
| **改**（把现有那条 `www → naytia.io` 换掉） | CNAME | `www` | 樱花面板给你的节点域名，形如 `cn-hk-nf-1.natfrp.cloud` | 默认（600 秒 / 1 小时） |

- 值**必须和隧道里「绑定域名」填的 `www.naytia.io` 配套**；`Host` 不匹配时节点会拒绝请求。
- 顺手把「域名停放 / Parked page」关掉，否则 GoDaddy 可能又给你补一条冲突的 A 记录。
- 验证：

```powershell
Resolve-DnsName www.naytia.io -Type CNAME      # 应返回樱花节点域名
nslookup www.naytia.io 8.8.8.8                 # 换公共 DNS 视角再确认一次
```

### 裸域名 `naytia.io` 怎么办

CNAME **不能挂在裸域名上**（DNS 规范不允许，GoDaddy 也不会让你这么填），所以裸域名有三条路：

| 做法 | 结果 | 注意 |
| --- | --- | --- |
| **不处理（推荐先这样）** | 只有 `https://www.naytia.io` 可用；裸域名继续显示停放页 | 最省事，站点用 www 作为正式地址完全正常 |
| GoDaddy **域名转发（Forwarding）** 301 到 `https://www.naytia.io` | 输入裸域名也能进站 | GoDaddy 会自带一条 A 记录（`13.248.243.5` 那类）实现转发，与站点无关；**它带浏览器缓存**，改回来可能被缓存卡住，要清缓存或换隐身窗口验证 |
| 隧道里**再绑一条** `naytia.io` + DNS 加 `A`/`AAAA` 指向节点 IP | 两条域名都直达站点，不经过转发 | 占用隧道绑定名额；节点 IP 变动时要手动改；`naytia.io` 在樱花面板里要单独添加并等待证书签发 |

如果要用裸域名，记得把根 `.env` 的 `SITE_URL` 一起改成 `https://naytia.io`（或保留 www
作为 canonical，另一条 301 过去），避免搜索引擎把两个地址当成两份内容。

### 方案 B：不做 CNAME，直接解析到节点 IP

| 类型 | 名称 | 值 |
| --- | --- | --- |
| A | `www` | 节点 IPv4 |
| AAAA | `www` | 节点 IPv6（节点有的话） |

简单，但节点 IP 变动时要手动改；CNAME 更稳，因此本次选 CNAME。

### 方案 C：Cloudflare 代理（小黄云）

若域名接在 Cloudflare 而不是直接用 GoDaddy DNS：**HTTP 隧道 + SSL/TLS 模式设成「灵活」**；
**HTTPS 隧道 + 灵活模式会 503**（参考[樱花的说明](https://doc.natfrp.com/app/http.html)）。
本站推荐「DNS only（灰云）」+ 樱花自动 HTTPS，链路最短、问题最少。

### 账号

正式库里只有两个账号（开发期的 17 个测试账号已被
`backend/scripts/curate_accounts.py` 清理，库里 119 篇文档与论坛内容都保留）：

重新整理开发数据（幂等，先备份再动手）：

```powershell

```

### 每次启动

```powershell
# 一键：构建 + 开两个窗口（后端 8000、站点入口 8080）
deploy\start-all.cmd

# 或者分开手动跑
npm run build
deploy\start-backend.cmd      # python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 ^
                              #   --proxy-headers --forwarded-allow-ips=127.0.0.1
deploy\start-site.cmd         # python deploy\server.py --host 127.0.0.1 --port 8080
```

两个窗口都要开着（关掉就等于站点下线）。隧道那边保持启动即可。

**改端口**：`python deploy\server.py --port 9000`，并把樱花隧道的本地端口同步改成 9000。

**只想本地看**：不必开隧道，直接浏览器开 <http://127.0.0.1:8080/>，和公网访问是同一套代码。

## 7. 已知边界与坑

- **HTTPS 与 Secure Cookie：当前是「临时放宽」状态，必须回正**（2026-09-16 实测记录）

  站点目前**只有 HTTP 可用**：樱花节点上还没有 `www.naytia.io` 的证书，
  443 端口对**所有**主机名都返回 `TLSV1_UNRECOGNIZED_NAME`（连节点自己的
  `frp-pet.com` 也没有证书），https 握手直接失败。而 Secure Cookie 不会在
  http 上回传，会造成「登录成功但刷新就掉」。

  因此 `backend/.env` 里现在是 `NAYTIA_COOKIE_SECURE=false`——**这是过渡值**。
  代价：会话令牌随请求明文传输，链路上没有 TLS 保护。

  **回正步骤**（下面两件事同时成立后再做）：

  1. 樱花隧道日志出现 `已从服务器为 www.naytia.io 加载证书`；
  2. `https://www.naytia.io/` 能正常打开（证书有效、无警告）。

  然后：把 `NAYTIA_COOKIE_SECURE` 改回 `true` → 重启后端
  （`deploy\start-backend.cmd`）→ 用**无痕窗口**在 https 下登录一次，确认刷新不掉。

  改回 `true` 之后 `http://www.naytia.io` 仍能看页面，但登录会失效。想彻底避免
  有人在 http 上登录，最省事的是在樱花里关掉 HTTP 访问（只留 HTTPS），
  或在 GoDaddy 前面挂 Cloudflare 并把 SSL 模式设为「完全」。
- **本机 DNS 缓存会让改动「看起来没生效」**：GoDaddy 记录已经改对，但路由器/系统
  仍按 1 小时 TTL 返回旧值（实测：本机解析到停放页 `13.248.243.5`，而 Google DNS
  已经是 `frp-pet.com → 64.49.47.22`）。`ipconfig /flushdns` 只清本机、清不掉路由器；
  要么等 TTL 过期，要么把电脑 DNS 临时改成 `8.8.8.8`。
- **IP 配额的边界**：只有 HTTP 隧道才带得到真实 IP（见第 3 节）。
  另外若访客自己伪造 `X-Forwarded-For` 且隧道不是 HTTP 类型（没有尾部真实 IP），
  他会以伪造地址记账——影响仅限配额计数，拿不到任何权限；`deploy/test_server.py`
  把这个取舍写成了用例而不是假装它不存在。
- **这条链路不抗压**：家庭上行带宽 + 樱花免费档限速（日志里量到 36 Mibit/s）就是上限；
  frpc 与节点断线时站点整体不可用。**静态内容不做多级降级**——本机一关就全站下线，
  这与 `02-总体架构` 里「云端功能失败时静态内容仍可用」的设想不一致，
  真要达到那个目标得把 `dist/` 另托管一份（未做）。
- **备案**：内地节点必须用已备案域名；境外节点不需要。这是节点约束，不是代码约束。
- **`.env` 不进库**：`backend/.env` 与根 `.env` 都在 `.gitignore` 里；
  换机器要手动补齐（照 `backend/.env.example`）。`backend/.env` 里有 DeepSeek 的 API key，
  **不要**把它的内容贴进聊天、截图或提交里。
- **数据要自己备份**：库是 `backend/data/app.db`（SQLite），附件在
  `backend/data/forum/` 与 `backend/data/docs/`。没有自动备份。
  整理数据的脚本（`backend/scripts/curate_accounts.py`）会先写一份
  `app.db.bak-<时间戳>`，但那只覆盖它自己那一次操作。

## 8. 出问题先看这里

| 现象 | 多半是什么 | 怎么办 |
| --- | --- | --- |
| 打开域名是 GoDaddy 停放页 | DNS 还没改，或 CNAME 还指向 `naytia.io` | 第 4 节；`Resolve-DnsName www.naytia.io -Type CNAME` 应返回樱花节点域名 |
| 502「后端服务不可达」 | 后端窗口没开或被关掉了 | 跑 `deploy\start-backend.cmd`；`curl http://127.0.0.1:8000/api/health` 应有 `{"status":"ok"}` |
| 页面能开，但登录后刷新就掉 | Cookie 没存下来：`NAYTIA_COOKIE_SECURE=true` 而你在用 http | 公网走 https 就正常；纯本地调试临时改 false 再重启后端 |
| 登录接口返回 200 但 `/api/auth/me` 是 null | 同上（Secure Cookie 未回传） | 同上 |
| 隧道连不上本地服务 | 本地端口和隧道里填的不一致 | 隧道填 `127.0.0.1:8080`；改过端口就两边同步 |
| 节点报域名不匹配 / 403 | 隧道「绑定域名」与 DNS 主机名不一致 | 两处都必须是 `www.naytia.io` |
| 浏览器证书错误 | 自动 HTTPS 还没签发完 | 隧道日志等 `已从服务器为 www.naytia.io 加载证书`；首次可能几分钟 |
| 上传大结构文件失败 | 超过 10 MB（论坛附件）或 32 MB（解析接口） | `backend/.env` 的上限；樱花免费档也有流量/限速 |
| 改了页面内容但线上没变 | 忘了重新构建 | `npm run build`（入口直接读 `dist/`，不用重启） |
| 改端口后打不开 | 忘了同步三处 | `start-site.cmd` 的 `--port`、`start-backend.cmd` 的 `--port`、`server.py --backend` |

## 9. 换域名 / 换隧道时改哪里

| 想改的东西 | 改哪里 |
| --- | --- |
| 正式域名 | 根目录 `.env` 的 `SITE_URL` → `npm run build`；樱花隧道「绑定域名」、GoDaddy 解析两处同步 |
| 隧道指向的端口 | `deploy\start-site.cmd` 的 `--port`，同步改樱花隧道的本地端口 |
| 后端端口 | `deploy\start-backend.cmd` 的 `--port`，同步改 `deploy/server.py --backend` |
| 会话有效期 | `backend/.env` 的 `NAYTIA_SESSION_DAYS` |
| 允许的跨域来源 | `backend/.env` 的 `NAYTIA_CORS_ORIGINS`（同源部署下用不到） |
| 上传体积上限 | `backend/.env` 的 `NAYTIA_MCSTRUCTURE_MAX_BYTES` 等 |
| 再加一个超管 | `backend/.env` 的 `NAYTIA_SUPERADMIN_CODE` → 重启 → 注册 → 清空重启 |
| 访客真实 IP 的采信规则 | `deploy/server.py` 的 `_TRUSTED_NETWORKS` / `--trust-proxy-xff`，改完跑 `python deploy\test_server.py` |

改完记得重启对应的窗口；只改前端内容时重新 `npm run build` 即可（入口直接读 `dist/`，
不用重启）。
