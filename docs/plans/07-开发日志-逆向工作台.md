# 07 · 开发日志：在线逆向工作台（BDS 反编译）

日期：2026-09-16  
状态：**已实装并验证**。决策记录见 [`ADR-004`](decisions/ADR-004-在线逆向工作台代理IDA-MCP.md)。

## 1. 需求与取舍

需求原话：「实现在线反编译基岩版 BDS 的功能，做一个简易的 IDA 前端，后端直接使用 IDA MCP 提供的接口」。

确认后的三个决策（用户答复）：

| 问题 | 选择 |
| --- | --- |
| 放在哪里 | 做成**工具箱里的一个工具**；补充：界面独立，从工具箱跳转过去 |
| 谁能用 | **访客只读；admin 可以改**（如重命名函数） |
| 目标实例 | **做成实例选择器，管理员能选** |

因为「界面独立 + 全屏三栏」与工具宿主的契约（纯函数引擎 + 可序列化 manifest + 卡片内运行）
不兼容，实现为：**工具箱目录里的入口卡片 → 独立页面 `/ida/`**。
为此给 `ToolManifest` 增加了两个可选字段 `gate` 与 `entryHref`，工具箱目录因此能同时收录
「站内工具」与「外部入口」两类条目，而不用伪造一套工具实现。

## 2. 现场事实（动工前实测，不依赖文档猜测）

| 项 | 实测结果 |
| --- | --- |
| IDA | `C:\Program Files\IDA Professional 9.2`（桌面快捷方式指向 `ida.exe`） |
| MCP 服务 | `ida-pro-mcp` v2.0.0（mrexodia），HTTP JSON-RPC at `http://127.0.0.1:13337/mcp` |
| 协议版本 | 协商得 `2025-06-18`；返回 `Mcp-Session-Id` |
| 工具数量 | **65 个**（完整 schema 存 `tests/manual/ida_mcp_tools.json`） |
| 运行中的实例 | 13337 `bedrock_server.exe`（active）、13338 `Minecraft.Windows.exe`、13339 `minecraft-edu.x86_64` |
| BDS 目标 | IDB `...\bedrock-server-1_21_1_03\bedrock_server.exe.i64`；**17 万函数中 16.5 万已命名**（符号未剥离）、Hex-Rays 就绪、字符串 49,232 条 |

**关键安全观察**：MCP 同时暴露 `patch` / `py_eval` / `py_exec_file` / `put_int` / `undefine`
等写入与任意执行能力。所以这不是"只读查看器"，边界必须显式设计（见 ADR-004）。

## 3. 实装内容

### 3.1 后端 `backend/app/reverse/`

| 文件 | 职责 |
| --- | --- |
| `mcp_client.py` | JSON-RPC over HTTP 客户端：会话管理、会话失效重连、实例切换、**串行化锁**、双白名单（只读/写入） |
| `schemas.py` | MCP 原始返回 → 前端契约的 pydantic 模型 + 归一化函数（字段名与形状差异都收敛在这里） |
| `client.py` | 服务层：把「MCP 调用 + 归一化」包成一个方法，路由不碰 MCP 细节 |
| `router.py` | `/api/reverse/*` 路由与权限分层 |

设计要点：

- **不引入 MCP SDK**：直接发 JSON-RPC，依赖更少、更可测。
- **串行化是正确性要求**：`select_instance` 是 MCP 侧全局状态，「切实例 + 调工具」必须在同一把锁内，
  否则并发请求会互相切走实例、返回别的二进制的结果。
- **白名单而不是黑名单**：请求参数里的工具名先在白名单里查，不在集合内直接 403 且**不发出请求**。
- **归一化层隔离版本差异**：例如 `search_text` 的返回在不同版本可能是 `hits`/`results`/`matches`，
  三种都读；`decompile` 失败时返回 `{error}` 而不是抛异常。

### 3.2 前端 `src/modules/reverse/` + `src/pages/ida.astro`

仿 IDA 的多面板工作区。界面先在 `prototypes/ida-demo/` 做成可独立打开的原型确认过，
再按此结构并入正式代码（原型保留为存档）。

**面板组成**

- 工具栏：实例选择（仅管理员）、函数搜索、上一个 / 下一个、复制、重命名（仅 admin）、快捷键
- 左栏三个页签：**函数 / 字符串 / 段**
- 主区五个页签：**伪代码 / 反汇编 / 交叉引用 / 栈变量 / 基本块**
- 状态栏：模块、基址、已加载函数数、当前选择、权限、IDB 路径

**亮点**

- **伪代码里 `/*0xADDR*/` 注释变成可点跳转**（Hex-Rays 的行内地址），
  配合 `lookup_funcs` 解析函数名，形成可漫游的浏览体验。`main` 一个函数就有 133 个可点地址。
- **轻量高亮**：注释 / 字符串 / 数字 / 关键字 / 函数名，反汇编另分助记符与寄存器分别着色。
  全部用 `createElement` + `textContent` 写入，**不用 innerHTML** —— IDA 的标识符与字符串可能含任意字符。
- **键盘操作**：`↑↓` / `JK` 连续翻函数（每次自动加载），`1`–`5` 切页签，`/` 聚焦搜索，
  `G` 跳地址、`C` 复制当前视图、`?` 帮助、`Esc` 关闭浮层。
- **渐进降级**：IDA 不可达时显示"IDA 未连接"与具体原因，不白屏、不影响站内其他功能。

**可拖拽面板**：侧栏宽度与函数列表高度都能拖（两条分隔条，`role="separator"`）。
尺寸写进 localStorage（`naytia:ida:side-width` / `naytia:ida:list-height`），刷新后保留；
双击或按 `Home` 复位；分隔条可聚焦，方向键微调（按住 Shift 步长更大）。
一次只可能拖一条，所以移动/抬起监听挂在 `document` 上只注册一次，由 `dragging` 状态驱动。

**样式位置**：`src/styles/ida.css`。不能写在页面的作用域 `<style>` 里 ——
Astro 只给模板里的元素加 `data-astro-*` 作用域属性，而工作台的 DOM 全部由脚本动态创建，
scoped 选择器选不中它们。

**异步竞态**：左栏三个页签与函数列表是并发加载的。若加载完成时用户已切走页签，
直接重画会把别的页签覆盖成函数列表（实测出现过：切到"段"后 6 个段被 200 行函数盖掉）。
因此各 `loadXxx()` 完成后都要先确认 `state.side` 仍是自己才画。

### 3.3 权限

| 角色 | 能力 |
| --- | --- |
| 访客 / 会员 | 查看状态、函数列表、伪代码、反汇编、交叉引用、栈变量、字符串搜索 |

### 4.1 过程中发现并修复的两个真实缺陷

1. **`asyncio.Lock` 死锁**：`_call_serialized` 持有锁后又调用 `ensure_session()`，
   而后者也去抢同一把不可重入的锁 → 第一次测试运行直接挂死（超时 5 分钟）。
   修法：把加锁责任上移到唯一的公开入口，`ensure_session` 不加锁并在注释里写明原因。
2. **伪代码地址跳转事件无人接收**：`clickableAddr` 派发 `rv:jump` 自定义事件，
   但工作台内部没有订阅者，点击无效。修法：在 `initReverseWorkspace` 内 `bindJumpHandler` 绑定。

3. **界面并入后的异步竞态**：左栏三个页签与函数列表并发加载，
   若函数列表在用户切到「段」之后才返回，重画会把 6 个段覆盖成 200 行函数。
   修法：每个 `loadXxx()` 完成时先确认 `state.side` 仍是自己才画；并加一个
   统一的 `paintList()` 只画当前页签。（首次实测就抓到了这个竞态的现场。）

### 4.2 顺带发现的并发问题（非本模块）

并行开发期间 `backend/app/routers/mcstructure.py` 曾出现 `from .config` / `.parsers` 的
导入层级错误，导致**整个 pytest 无法收集**（`ModuleNotFoundError`）。该文件由另一路开发维护，
在我读取时已被其修复。记录在此，因为「一个模块的错误导入会让全量测试失效」值得注意。

## 6. 已知限制

- **必须后端与 IDA 同机**：工作台代理的是本机 `127.0.0.1:13337` 的 MCP，
  不是公网可用的 IDA 服务。异地部署需要额外的隧道方案，且必须重新评估安全边界。
- **多用户共享一个实例**：`select_instance` 是 MCP 侧全局状态，
  后端用锁保证正确性，但两个管理员同时操作会互相切换实例（不会串数据，但会互相干扰）。
  真要多人隔离需要每实例独立 MCP 端点。
- **读接口对访客开放**：BDS 反编译结果对未登录访客可见（用户明确选择）。
  如需收紧，给读接口加 `require_account` 即可。
- **首次进入较慢**：`survey_binary` + 首页函数列表约需 2–4 秒（IDB 有 17 万函数）。
- **没有虚拟滚动**：函数列表一次 200 条、靠「加载更多」翻页；跳到第 800 页需要点 4 次。
  函数名搜索走 MCP 的 glob 过滤，所以实际使用中以搜索为主。
- **不开放字节修改**：`patch` / `py_eval` 等刻意不开放（见 ADR-004），
  这是有意的边界而不是遗漏。
- **重命名会真实写入 IDB**：这是"分析成果沉淀"的设计目标，但意味着管理员的误操作会影响数据库；
  当前没有「撤销」接口（手工改回原名即可）。

## 7. 后续建议

1. 若函数列表需要更顺滑，给 `.rv-list` 加虚拟滚动（只渲染视口内的行）。
2. 增加「导出」：把当前函数的伪代码/反汇编导出为文本或 C 头文件（MCP 有 `export_funcs`，属只读）。
3. 若多人使用成为常态，按 ADR-004 的重新评估条件拆分实例端点。
4. 若要让访客也看不到反编译内容，给读接口加登录要求（一次改动，无需重构）。
