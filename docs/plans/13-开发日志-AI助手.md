# 13 · 开发日志：逆向工作台的 AI 助手

日期：2026-09-16  
状态：**已实装并验证**。决策记录见 [`ADR-008`](decisions/ADR-008-AI助手代理DeepSeek与配额.md)。

## 1. 需求与取舍

需求原话：「让普通访客也可以使用逆向工作台，但是只读，再增加一个问 AI 的悬浮窗口，
里面内置简单的 agent 功能，并配一个 deepseek 的 api，普通用户每 5 小时只能有三轮对话」。

拆成三件事：

| 需求 | 结论 |
| --- | --- |
| 访客可用逆向工作台、只读 | 后端只读接口本来就无鉴权；只需**拆掉工具箱卡片的 `gate: 'admin'`**。写操作（重命名、切实例）仍只对 admin 显示，服务端另有拦截 |
| 悬浮 AI 窗口 + 简单 agent | 底部右侧悬浮球 → 面板；agent 用 DeepSeek function calling 调只读工具自己去查 IDA |
| 每 5 小时 3 轮 | 服务端滑动窗口配额；登录按账号、未登录按 IP |

## 2. 现场事实（动工前核对，不靠记忆）

| 项 | 结论 |
| --- | --- |
| DeepSeek 接口 | OpenAI 兼容 `POST {base}/chat/completions`，Bearer 鉴权，`deepseek-chat` 支持工具调用（[Tool Calls 文档](https://api-docs.deepseek.com/guides/tool_calls/)） |
| `openai` SDK | **不在本项目的依赖清单里**（环境装了，但不能依赖）→ 用已声明的 `httpx` 直连 |
| 逆向工作台的只读接口 | 本来就无鉴权，`require_staff` 只挂在重命名路由上 |
| 工具箱门槛 | `src/tools/catalog.ts` 里逆向条目带 `gate: 'admin'` |

## 3. 实装内容

### 3.1 后端 `backend/app/ai/`

| 文件 | 职责 |
| --- | --- |
| `deepseek.py` | `/chat/completions` 客户端：鉴权、超时、上游状态码→结构化错误、工具参数容错解析 |
| `tools.py` | **只读**工具集：10 个工具的 OpenAI function 定义 + 实现（全部委托 `ReverseService`） |
| `agent.py` | agent 循环：system 提示 → 模型 → 执行工具 → 回灌结果 → 直到给出自然语言回答 |
| `ratelimit.py` | 滑动窗口配额（可注入时钟，测试不必等 5 小时） |
| `schemas.py` | API 契约（请求/响应/配额） |
| `router.py` | `/api/ai/quota`（公开）与 `/api/ai/chat` |

设计要点：

- **只读是结构性的**：`tools.py` 里没有 `rename`/`patch`/`py_eval`，
  而且底层 `IdaMcpClient.call()` 还有一层只读白名单，写操作必须走 `call_write`。
  agent 想改 IDB 也没有路径可走——不是靠提示词约束。
- **一轮 = 一条消息**：agent 内部可能调用多次工具，但只扣一次配额。
  用尽工具轮数时如实返回"没能得出结论"，不假装有结论。
- **上下文单独成条**：工作台状态作为一条独立 system 消息放在用户消息之前，
  **不拼进用户那句话**（第一版拼进去了，导致前端把历史原样显示时，
  用户的提问气泡里混进一大段"[工作台当前状态]…"）。
- **历史不落库**：只存浏览器 localStorage，每轮整体回传，服务端截断。

### 3.2 前端 `src/modules/reverse/`

- `ai-api.ts`：`/api/ai/*` 客户端 + 剩余时间的人话格式化。
- `ai-panel.ts`：悬浮球 + 可折叠面板。回答里的 `0x…` 地址可点击→跳转到该地址；
  工具调用以「🔍 反编译函数」形式留在对话流里，让用户看到 AI 查了什么而不是黑箱。
- 工作台启动时挂载，`getContext()` 把当前选中的函数名/地址/模块带给模型。

端到端实测（`mock-deepseek.mjs` 假扮 API，**不消耗真实额度**）：

- 悬浮球存在、面板默认收起、点开后球隐藏；
- 配额显示「剩 3/3 轮」，提示「每 5 小时 3 轮，当前还剩 3 轮」；
- 选中 `main` 后提问「这个函数在做什么？」→ 回答正确，
  对话流里出现工具记录 **「🔍 反编译函数」**，回答里的地址可点跳转；
- 配额 3 → 2，用满 3 轮后显示「剩 0/3 轮」；
- 第 4 轮被拦：提示「额度已用完，约 5 小时后恢复」，发送按钮与输入框**同时**禁用；
- 历史落 localStorage（`user, assistant, tool, assistant`）；
- **0 页面报错**。

对照真实契约的原始响应（`curl` 直打后端）：

```
tool_calls: [{"name":"decompile","label":"反编译函数","args":{"addr":"0x7ff6871d3b90"},"ok":true}]
message roles: user, assistant, tool, assistant
```

### 4.1 过程中发现并修复的四个真缺陷

1. **工作台上下文字符串污染用户消息**：上下文拼进了 user 消息，
   前端把历史原样显示 → 用户的提问气泡里出现一大段 `[工作台当前状态]…`。
   修法：上下文单独作为一条 system 消息插在 user 之前，并在回传前端时过滤掉 system。
2. **工具调用记录被重绘抹掉**：先 `append` 工具节点、再 `paintLog()`，
   而后者会 `replaceChildren()` 清空重建 → 节点刚加上就没了（实测 `toolNodes: []`）。
   修法：先记下节点 → 重绘历史气泡 → 再把工具记录追加到末尾。
3. **发送按钮与输入框禁用状态不一致**：额度用尽时按钮禁用但输入框仍可打字，
   看起来像卡死。修法：两者用同一个 `blocked` 条件。
4. **提示文案口径不对**：用完第一轮只显示「本轮已用 1 次」，与「每 5 小时 3 轮」的
   总账对不上。修法：改成「每 5 小时 3 轮，本轮已用 1 次，还剩 N 轮」。

另外记一笔**排查教训**：验证期间一度看到 `tool_calls` 为空，怀疑后端有 bug；
实际是**假 DeepSeek 的回复队列被前几次测试用尽后重复最后一条**（最后一条是纯回答），
所以模型没触发工具调用。用干净 mock 复测即恢复正常。诊断时先确认测试替身的状态，
比逐行读业务代码更快。

## 6. 已知限制

- **配额在进程内存里**：重启后端即重置。单机够用；多实例部署会失效（见 ADR-008 的重新评估条件）。
- **反代后 IP 不准**：当前用 `request.client.host`，放在反向代理后面会拿到代理 IP，
  导致所有访客共用一个配额桶。**上线到反代前必须改**。
- **agent 只有 10 个只读工具**：不支持改名/打补丁（有意为之）；
  也不支持"帮我在 IDA 里跳过去"这类界面操作。
- **不做流式输出**：回答一次性返回。深思考/长回答时用户要等，面板有"思考中…"占位。
- **不落库**：换浏览器或清 localStorage 后历史丢失；服务端也没有对话记录可审计。
- **费用**：key 泄露是唯一不可逆的风险。建议在 DeepSeek 控制台设置消费上限。

## 7. 后续建议

1. 上线到反向代理前，改为读取可信代理头取真实 IP，并记入 ADR。
2. 若多实例部署，把配额换成 Redis/数据库计数。
3. 可选：把回答改成流式（SSE），长回答体验更好。
4. 可选：给登录用户更高配额（如 10 轮），鼓励注册；改一个常量即可。
