# 02 · 总体架构与扩展规范

更新日期：2026-09-16  
状态：建议架构，正式初始化前锁定依赖版本与部署平台。

## 1. 总体选择

采用「静态内容页面 + 按需交互工具 + 可替换数据适配器」的模块化单体。初期一个仓库、一个网站，不先拆微服务或多仓库。

建议使用 Astro 管理内容和页面，TypeScript 管理数据契约与算法，React 仅用于有复杂交互的工具工作区。采用此组合是针对内容站与工具站并存的设计建议，不是已完成的技术决策。

服务端语言已定为 **Python**（2026-09-16，见 [ADR-001](decisions/ADR-001-后端语言选型Python.md)）：账号、论坛、个人数据三类 API 由 Python 服务承载（建议基线 FastAPI），数据库已定 SQLite，博客/作品/工具目录仍为静态预生成。跨语言契约以 JSON API + OpenAPI 为单一事实源，前端类型由 OpenAPI 生成。托管平台仍属 D07 未决部分。

Astro 支持结构化内容集合以及局部交互组件，适合把博客正文与需要运行代码的工具界面分开。[内容集合文档](https://docs.astro.build/en/guides/content-collections/)、[Islands 架构文档](https://docs.astro.build/en/concepts/islands/)

内容优先预生成。未来确需服务端接口时，按目标运行平台接入适配器与按需渲染；静态输出自身不提供后端功能。[按需渲染文档](https://docs.astro.build/en/guides/on-demand-rendering/)

论坛与账号（2026-09-16 纳入范围）需要服务端读写与认证：后端语言与数据库已定（Python + SQLite，ADR-001）；托管平台在实现前定案（对应 05 文档 D07）。在此之前以本地 localStorage 适配器提供演示实现，契约不变。

## 2. 分层与依赖方向

```text
页面 / 路由 / SEO
       ↓
功能模块：博客、作品、工具目录、工具工作区、论坛、账号
       ↓
应用用例：查询内容、执行工具、导出结果
       ↓
领域模型与接口：内容契约、规则、纯计算、错误类型
       ↑
基础设施适配器：文件、CMS、Worker、HTTP、资源存储

装配层：选择适配器、注册模块、注入依赖
```

- 领域层不导入 Astro、React、DOM、数据库客户端或特定云服务 SDK。
- 页面负责呈现与输入，不直接实现算法或文件解析。
- 数据访问由模块定义的窄接口提供；不建立一个包办所有资源的万能服务。
- 跨模块引用使用稳定 ID 与公开查询接口，不深层导入其他模块的内部实现。
- `shared/` 只放多个模块确实复用的基础能力，不作为杂物目录。
- 服务端私有代码与浏览器代码分目录；构建检查禁止密钥及服务端 SDK 进入客户端包。

## 3. 建议目录

以下目录是未来结构，本次不创建源码骨架。先以单包维护；只有存在第二个使用者、独立发布或明确性能边界时，才提取 workspace package。

```text
docs/plans/                  # 当前规划、阶段记录、架构决策
prototypes/pixel-demo/        # 未来迁移时保存现有 Demo 和头像
content/
  posts/                     # 博客正文与 frontmatter
  works/                     # 作品正文与资源清单
public/                      # 可公开的静态文件
src/
  pages/                     # 首页、blog、works、tools、404
  config/                    # 站点资料、导航、开关、推荐顺序
  components/ui/             # 基础按钮、字段、卡片、错误提示
  layouts/                   # 公共页壳、文章与工具布局
  styles/                    # tokens、基础样式、主题
  modules/
    blog/                    # schema、查询、展示
    works/                   # schema、资源、展示
    toolbox/                 # 目录、注册表、工具宿主
    forum/                   # 版块、帖子、回复、展示
    account/                 # 注册登录、会话、账号级偏好（如工具收藏）
  tools/
    chunk-coordinates/       # manifest、schema、engine、UI、tests
    material-counter/
  domain/                    # 共享 MC 概念与内容引用等纯类型
  ports/                     # 内容、资源、计算执行的边界接口
  adapters/                  # files、workers、local（演示用 localStorage）；未来 cms、http、auth
  shared/                    # 经过验证的通用基础能力
  server/                    # 仅在真正引入服务端后建立
tests/fixtures/              # 小型可复现实例与权威对照数据
scripts/                     # 内容校验、发布前检查等
dist/                        # 未来仅作为可重新生成的产物
ancient_debris/              # 现有研究资料；不自动进入构建/公开目录
```

正式构建通常会覆盖 `dist/`。第一次运行构建前，必须先把当前手写 Demo 和头像复制到 `prototypes/pixel-demo/`，验证备份内容，再将 `dist/` 转为输出目录。不能直接在现有 `dist/` 上初始化或清理。

## 4. 每类能力的扩展点

| 能力 | 稳定边界 | 扩展方式 |
| --- | --- | --- |
| 导航与首页 | `SiteConfig`、已知区块注册表 | 配置路由和精选内容 ID；不能用配置执行任意代码 |
| 博客 | `Post`、`PostRepository` | 新内容文件或新数据源适配器 |
| 作品 | `Work`、`ResourceRelease` | 新作品类型、资源类型及其专用展示组件 |
| 工具目录 | `ToolManifest` | 显式添加注册项，自动生成列表与路径 |
| 工具计算 | 纯函数/任务接口 | 新 engine 或 Worker/WASM 执行适配器 |
| 论坛 | `ForumThread`、`ForumReply`、`ThreadRepository` | 新版块配置、新数据源适配器（本地演示 → 服务端） |
| 账号 | `Account`、`SessionProvider` | 本地演示会话替换为服务端认证适配器，页面不感知实现 |
| 主题 | CSS tokens、UI 组件契约 | 新主题变量；组件不散落硬编码颜色 |
| 搜索 | 统一轻量索引项 | 初期构建时索引，未来替换搜索适配器 |
| 下载 | 资源清单与下载解析接口 | 静态文件、对象存储或镜像适配器 |
| 持久化 | 明确的仓储接口 | 文件源到 CMS/数据库迁移 |
| 外部服务 | 集成适配器 | 视频、评论、分析等可逐个替换或停用 |

首页区块只支持已审核的组件集合。真正出现第三种复杂区块后再抽象通用区块协议，不提前建可视化页面编辑器。

## 5. 工具模块约束

1. 每个工具必须自包含；其他工具不引用它的 UI 或私有实现。
2. 共享算法先有共同需求和一致语义，再放入公共领域库。
3. 描述信息与实现分离：列表页只读取轻量 manifest，进入详情页才加载 UI 与引擎。
4. 注册表使用显式导入映射；不接受 URL 参数拼接模块路径或下载执行第三方插件。
5. 规则数据和引擎实现版本分开管理；实验性结果明确标识，缺失版本不静默替代。
6. 单个工具加载/计算失败由宿主捕获，提供重试或说明，其他模块继续工作。
7. 有 URL 参数导入时先校验；文件内容、种子等潜在私密参数默认不放入公开链接。

## 6. 数据源迁移策略

第一阶段使用本地文件。页面调用仓储接口得到规范化结果，避免依赖具体 frontmatter 位置或 CMS 响应结构。

未来更换数据源时：导出旧数据 → 校验稳定 ID 与关联关系 → 新适配器并行比对 → 构建预览 → 切换 → 保留回退快照。字段破坏性变更提供迁移脚本，不能让旧内容在构建中悄悄丢失。

## 7. 状态与服务端边界

- 文章与作品无须客户端全局状态；工具表单状态归工具自己管理。
- 论坛与账号引入跨页面会话状态：演示版由 localStorage 承载并在界面明示边界；正式版替换为服务端会话与认证适配器，接口不变。密码与凭据只存在于服务端，演示版仅存本地散列且必须提示用户勿复用真实密码。
- 跨工具共享状态仅限已存在的需求，例如显示偏好；计算任务与结果不混放全局 store。
- 浏览器本地存储仅用于明确的本机偏好或用户主动保存；加入版本号和清除入口。
- 数据库、鉴权、限流等随论坛与账号的正式实现一并引入（见 05 文档阶段 4）；密钥不出现在客户端配置。
- 云端功能失败时，静态内容与本地工具仍可使用；不存在隐式强依赖的启动链。

## 8. 复杂计算的升级路径

先实现纯 TypeScript 算法，测量真实输入，再根据瓶颈接入 Worker、WASM 或服务端任务。Web Worker 通过消息与页面通信，不能直接操作 DOM；消息协议需要明确序列化、错误和生命周期。[MDN Worker 文档](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)

研究脚本转工具必须先补齐输入定义、版本依据、复现实例、误差边界和许可证/来源说明。现有 `ancient_debris/` 仅是候选研究来源，不在本计划中承诺转换结果或功能。

## 9. 扩展验证

新增第三个工具时验证：无需改动前两个工具文件；宿主提供加载、错误与版本显示；不运行该工具的页面不下载其重型依赖。

替换头像/主题、增加文章/作品、增加一种引擎规则分别做一次小型演练。若这些变化需要修改不相关模块，应先修复边界再继续增加功能。
