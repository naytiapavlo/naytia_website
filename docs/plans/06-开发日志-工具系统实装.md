## 2. 本次实装内容

### 2.1 工具宿主（`src/tools/_host/`）

| 文件 | 职责 |
| --- | --- |
| `types.ts` | 03 文档第 4/5 节的契约：`ToolStatus` / `ExecutionMode` / `ToolError` / `ToolResult` / `ComputeContext` / `ToolEngine` / `ToolSchema` / `ToolHostConfig` |
| `manifest.ts` | 可序列化的 `ToolManifest`、状态标签、`isRunnable()`（规划中工具不挂载界面） |
| `result.ts` | `ok/fail/schemaFail` 构造、严格整数解析、`floorDiv` / `positiveMod` |
| `ui-kit.ts` | 表单、结果卡、表格、警告、错误、可访问结果区（`role=status`） |
| `host.ts` | 加载、状态门槛、`schema.parse → engine.run` 统一管线、失败隔离、收藏入口 |
| `favorites-api.ts` | `/api/favorites` 客户端（对齐后端契约） |

关键设计：

- **结果用判别联合而不是抛异常**：输入不合法、规则不支持都是正常返回；只有内部故障才 catch 并转成 `internal_error`。
- **错误按字段定位**：`ToolError.field` 携带字段路径，界面精确标红对应输入框并聚焦。
- **数字不猜测修复**：空串、小数、负数、超范围、超安全整数一律拒绝并说明原因，不四舍五入。
- **诚实标注执行位置**：两个工具都是纯函数，`executionMode: 'inline'`；没有假装成 Worker。

### 2.2 区块与坐标助手（`src/tools/chunk-coordinates/`）

- 输入：方块 X/Z（±29,999,999）+ 维度。
- 输出：区块坐标、区块内坐标（0~15）、区块原点、区域文件坐标与文件内下标、主世界↔下界换算。
- 状态 `stable`（规则只有「向下取整」一条，且有独立对照测试）。
- 负坐标是本工具的核心风险点：`-1` 属于区块 `-1`、区块内坐标 `15`，工具与测试都显式覆盖。

### 2.3 材料清单助手（`src/tools/material-counter/`）

- 输入：多条材料（名称 + 数量 + **各自**的堆叠上限）+ 容器类型。
- 输出：每条材料的组数/零头/占用格数、合计、需要的容器数量与剩余空位。
- 状态 `stable`。
- 明确不写死「所有物品都是 64 堆叠」（01 文档第 6 节要求）：堆叠上限逐条填写，1（不可堆叠）/16（末影珍珠）/64 都在测试里。
- 容器数量按占用格数换算，并在界面与文档里说明**不假设多种材料之间的最优装箱**。

### 2.4 路由与页面

- 新增 `/tools/[slug]/`（`getStaticPaths` 为每个注册工具生成静态路由）：元数据 + 文档由服务端渲染，输入界面由宿主在客户端挂载。
- 改写 `/tools/`：可运行工具是链接卡片，规划中工具是静态卡片并写明「尚未上线，暂无运行入口」。

### 2.5 工具箱与账号联动

- 未登录：收藏按钮为锁定态，点击打开 account 模块的登录弹窗。
- 已登录：可收藏/取消收藏，状态写入后端 `/api/favorites`（按账号隔离）。
- 订阅 `naytia:session` 广播，登录/退出后按钮立即同步，无需刷新。
- 后端离线时只有收藏功能降级提示，**工具计算完全不受影响**（02 文档：不存在隐式强依赖的启动链）。

### 2.6 测试

- `tests/tools.test.ts`：16 项引擎对照测试，覆盖 04 文档要求的边界（`-17 / -16 / -1 / 0 / 15 / 16`、`0 / 1 / 恰好一组 / 刚过一组 / 不可堆叠 / 大数量`）与非法输入。
- `tests/resolve-ts.mjs`：Node 解析钩子，让无扩展名导入在测试侧可解析，**不引入测试框架依赖**（`node --test` 直接跑 TypeScript）。
- `npm test` 已加入 `package.json`。

### 3.1 验证期间发现并修复的两个真实缺陷

1. **主世界→下界换算写反**：初版把 `coordinateScale` 当作除数用，主世界 `800` 算成了下界 `800`（应为 `100`）。测试期望值是手算的，先失败后修复。
2. **收藏按钮不跟随登录状态**：宿主只在挂载时读一次会话，登录后按钮仍停留在锁定态。改为订阅 `naytia:session` 广播。
   修复过程中还发现一个打包陷阱：从 `modules/account` 入口**再导出**的事件名常量被 tree-shaking 摇掉（`ui.ts` 内部用的是局部变量），导致监听器静默失效；改为在宿主内写字面量并注明同步来源。

### 3.2 一个必须记录的本地开发限制

会话 Cookie 是 `SameSite=Lax`。开发时前端在 `4321`、后端在 `8000`，**跨端口时浏览器不会在 fetch 中携带该 Cookie**，表现是「注册成功但一直显示未登录」（`/api/auth/me` 返回 `null`）。

- 这是浏览器行为，**不是应用缺陷**；线上前后端同域时不存在。
- 本节第 3 条的浏览器验证因此在**同源**条件下完成：用临时脚本把 `dist` 与 `/api` 反代到同一端口（`tests/manual/serve-dist.mjs`），并把 `.env` 的 `PUBLIC_API_BASE` 临时置空走相对路径，验证后已改回。
- 结论：`cookie_secure=false` + `SameSite=Lax` 的配置在**同域部署**下可用；如果将来前后端分域部署，必须重新评估 Cookie 属性（`SameSite=None; Secure`）与 CORS，并补进 ADR。
